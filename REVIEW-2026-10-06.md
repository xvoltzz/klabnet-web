# Codex follow-up review — v2026.10.06.7

This pass fixes confirmed frontend issues and adds repeatable regression
checks. It does not establish that every remaining bug has been found.

## Behavior fixes

- Chat drafts, images and reply context stay with their conversation.
  Failed sends restore to the source conversation even after switching rooms.
- Read receipts ignore edits and unsent local echoes, deduplicate in-flight
  requests, and mark success only after the request succeeds.
- Incomplete DM invite metadata and failed join/account-data requests can
  retry. Join retries have a 30-second cooldown.
- Pagination tracks each room independently; a response for a room left
  behind no longer rebuilds the current conversation.
- Tab and screen history share descriptors and depth. Phone Chat Back
  traverses to its existing room-list entry, and Forward restores the chat.
- Rapid stars serialize per item. Explicit Star/Unstar actions keep their
  intended state, unknown states do not blindly flip, and stale GETs cannot
  overwrite an optimistic change made in the same millisecond.
- Closing an image viewer cancels its original download. Fetch timeouts now
  preserve the caller's abort signal. Clipboard conversion closes its bitmap.
- Slideshow image, fullscreen and wake-lock callbacks cannot affect a later
  reopening. Rapid Next presses keep the newest requested photo.

## Performance and consistency

- New chat messages append to existing rows. Edits, redactions, reactions,
  pagination and limited timeline resets retain the full rebuild path.
- Home uses Feed's cached posts and shares its in-flight refresh, instead
  of separately downloading eight posts.
- Album/artist rows removed from Music release their thumbnail observers.
- Music request avatar resolution updates faces without rebuilding rows.
- Slider fills use `scaleX` instead of changing layout width. Keyboard arrows,
  Home and End control sliders, with accessible values and labels.
- Settings switches, mute controls and dock art are native buttons. Switch
  and mute states expose their current accessible state; M uses the same
  unmute behavior as the button, including restoring volume from zero.
- Chat header/hello buttons, Feed's Show more, and request/feedback selectors
  use Music's button height, font, radius and hairline. Selected selectors use
  the filled style. Narrow desktop dock spacing keeps buttons within its edge.

## Validation

See `tests/README.md` for commands. Syntax and asset-version checks pass.
Delayed-network unit checks and browser regressions pass with an isolated
local API. Browser checks exercise tab/album/phone history, chat append and
fallback rebuilds, receipts, drafts, invites, pagination, viewer cancellation,
request avatars, observer cleanup, slideshow races, and keyboard controls.

Screenshots and smoke checks cover all five tabs, Music lists, Settings and
the request dialog in light/dark themes, sidebar navigation, and fake Windows,
GNOME, KDE and macOS bridges. Narrow desktop checks cover 700px and 390px;
phone Chat is emulated at 390px. No uncaught script exceptions were recorded.

## Remaining verification and open work

- Real Matrix SSO/sync, SDK send scheduling/local-echo cancellation, receipts
  between real clients, invite first-message notifications, encrypted rooms,
  reconnect after sleep, and SVG avatar behavior still need a staging session.
- Physical phones, native desktop materials/title-bar zoom, screen locks,
  listening parties, and long-session GPU/memory profiling are unverified.
- The API's single presence row per user and photo queries limiting before
  filtering remain server-side work. The desktop wake-lock allow-list remains
  a separate-repository check.
- Other items in `AGENTS.md`, including unused code, remaining non-button
  controls, font weights and the sound-effect AudioContext lifecycle, remain
  open unless listed as fixed above. Chat still rebuilds for mutations; this
  pass optimizes the common append case rather than implementing a virtual list.

This report records local review and validation results before deployment.
